# HomeBrain AI

HomeBrain AI is a demo-ready household command centre. Describe a household goal, such as **“I am leaving home for 5 days.”**, and get security, energy, and entertainment recommendations in one place.

This hackathon MVP simulates Alexa+, Ring, Fire TV, and Bee. It does not connect to or control real devices. Plans are generated by Gemini when a backend API key is configured; without a key, a deterministic demo planner keeps local development and demos working.

## Architecture

```text
backend/
  app/
    agents/       Household planning orchestration
    api/          FastAPI routes
    database/     SQLAlchemy engine and sessions
    models/       SQLAlchemy persistence models
    schemas/      Pydantic request and response types
    services/     Gemini, plan, and simulated device services
  tests/          API and SQLite tests
  main.py         FastAPI application entry point
frontend/
  app/            Next.js app router, page, and global styles
  components/     Dashboard and shadcn-style UI primitives
  lib/            API client and shared utilities
  types/          Frontend API contracts
```

The FastAPI API is documented at `http://localhost:8000/docs` while the backend is running.

## Requirements

- Ubuntu (or WSL2 with Ubuntu)
- Python 3.11 or later
- Node.js 20.9 or later and npm
- Optional: a Google Gemini API key for AI-generated plans

## Ubuntu installation

From the repository root:

```bash
# Backend environment and dependencies
cd backend
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
cp .env.example .env
cd ..

# Frontend dependencies and local environment
cd frontend
cp .env.local.example .env.local
npm install
cd ..
```

Edit `backend/.env` and set `GEMINI_API_KEY` to enable Gemini. Keep this key server-side; do not put it in a `NEXT_PUBLIC_` variable or commit it. The frontend defaults to `http://localhost:8000`.

## Run locally

Open two Ubuntu terminals at the repository root.

**Terminal 1 — API**

```bash
cd backend
source .venv/bin/activate
uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

**Terminal 2 — web app**

```bash
cd frontend
npm run dev
```

Open `http://localhost:3000`. SQLite is created as `backend/homebrain.db` when the API starts. The database file is local runtime data and should not be committed.

## API overview

| Method | Endpoint | Purpose |
| --- | --- | --- |
| `GET` | `/api/health` | API health check |
| `GET` | `/api/devices` | Simulated ecosystem device statuses |
| `POST` | `/api/plans` | Generate and save a household plan |
| `GET` | `/api/plans?limit=10` | Return up to 50 recent plans |

Example request:

```bash
curl -X POST http://localhost:8000/api/plans \
  -H 'Content-Type: application/json' \
  -d '{"goal":"I am leaving home for 5 days."}'
```

The response includes an id, original goal, timestamp, classified `intent_category`, `security_plan`, `energy_plan`, and `entertainment_plan` string arrays, an `ai_summary`, and 3-5 `alexa_automations` suggestions. These are optional routine ideas, not device commands; no routines are enabled automatically. Gemini classifies each goal into an intent such as travel, family, newborn, event, work schedule, energy saving, or home security. The prompt and recommendations are tailored to that intent. Without an API key, or if Gemini fails, the backend uses an intent-aware local fallback rather than a generic plan.

The dashboard also displays a **Device Actions** panel with simulated Alexa+, Ring, Fire TV, and Bee states selected from the saved plan intent. Suggested, ready, and standby states are illustrative only; the app does not send commands to real devices.

Backend JSON logs include the submitted goal, detected intent, raw Gemini response when available, final plan JSON, and whether Gemini or the local fallback produced the plan. Goals and model responses may contain personal information; protect access to logs and apply appropriate retention/redaction policies in deployed environments.

## Common issues

- **Port already in use:** Stop the other service using port `8000` or `3000`, or choose a free port and update the frontend API URL and backend CORS origins.
- **Frontend cannot reach the API:** Check that the backend is running, `frontend/.env.local` has the correct `NEXT_PUBLIC_API_URL`, and `backend/.env` includes the frontend origin in `CORS_ORIGINS`. Restart Next.js after changing environment variables.
- **Gemini plan generation fails:** Check the backend-only `GEMINI_API_KEY`, model availability, network access, and backend logs. When Gemini is not configured or a request fails or times out, the app logs the provider failure and uses its intent-aware local planner without changing the plan response shape.
- **SQLite permission or path error:** Run the API from `backend/` for the default relative database path, and ensure that directory is writable. Set an absolute `DATABASE_URL` when running elsewhere.
- **Python package/import errors:** Activate the backend virtual environment and install `backend/requirements.txt`. Start Uvicorn from `backend/` so `main:app` and the `.env` file resolve correctly.
- **Node version or missing modules:** Use Node.js 20.9 or later, then run `npm install` from `frontend/`.

## Demo deployment guide

This deployment shape keeps Gemini credentials on the backend and serves the frontend separately.

1. **Deploy the API** to a Python host (for example, Render) with `backend/` as its root directory. Install with `pip install -r requirements.txt` and start with `uvicorn main:app --host 0.0.0.0 --port $PORT`.
2. Add backend environment variables: `GEMINI_API_KEY`, `GEMINI_MODEL`, `ENVIRONMENT=production`, `CORS_ORIGINS=https://<your-frontend-domain>`, and `DATABASE_URL`.
3. Attach persistent storage for SQLite and set `DATABASE_URL` to its absolute path, for example `sqlite:////var/data/homebrain.db`. Ephemeral filesystem databases are lost when many hosts redeploy or restart. For a longer-lived production service, use a managed database and configure its SQLAlchemy URL.
4. **Deploy `frontend/`** to a Next.js host (for example, Vercel). Set `NEXT_PUBLIC_API_URL` to the deployed backend origin and deploy.
5. Confirm the browser can call `/api/health`, CORS permits the deployed frontend origin, plan history survives an API restart, and the Gemini key is not exposed in browser assets.
6. Before presenting, generate and save a sample plan, verify the mobile layout, and clearly disclose that device statuses and actions are simulated.

Pin dependencies and add authentication, user isolation, rate limiting, and operational monitoring before using this prototype with real household data or exposing it as a public production service.
